一、项目概述
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本项目是一个面向银行监管申报的桌面工具，用于：

  1. 生成存款归属表     — 根据 A1411/A2411 月报数据自动计算并填充
  2. 生成科目余额核对表  — 从科目余额表提取数据，填入核对表模板
  3. 执行数据校验        — 跨数据源交叉校验（IRP001/IRP002/科目余额表等）
  4. 生成校验报告        — 输出标红（不一致）的 Excel 校验报告

业务背景：
  银行每月需向存款保险机构报送被保险存款申报数据，涉及多个监管报表。
  本工具自动从各报表中提取数据，计算并生成所需表格，同时进行交叉校验，
  确保不同数据源之间的数据一致性。

技术架构：
  - 编程语言：Python 3.8
  - GUI框架：PyQt5
  - Excel处理：openpyxl (.xlsx) + xlrd (.xls)
  - 打包工具：PyInstaller（发布为独立 exe）

  (1) 生成存款归属表     → 需要 A1411 + A2411
  (2) 生成科目余额核对表  → 需要 科目余额表（源数据）
  (3) 执行数据校验       → 需要 IRP001 + （可选）IRP002/存款归属表/核对表

后台线程：
  4个 QThread 子类（DepositComputeThread、AcctCheckThread、

3.2 deposit_calculator.py — 存款归属表计算引擎
───────────────────────────────────────────────

文件位置：根目录/deposit_calculator.py
类：DepositCalculator

功能：
  读取 A1411 和 A2411 月报表数据，按存款归属表模板结构计算并填充。

核心方法：
  - load_a1411(filepath)      — 加载 A1411 数据
  - load_a2411(filepath)      — 加载 A2411 数据
  - load_attachments(att2, att3) — 加载附件2/3 数据
  - compute(template, output, ...) — 执行计算并输出

计算流程（4步）：
  Step 1: 读取模板，解析科目代码及 C/F 列公式
  Step 2: 非计算行按科目代码从数据源独立取数（不做子项间汇总）
  Step 3: 计算行按模板公式计算（公积金/社保按公式对子项求和，
          不直接取附件数据；公式间依赖自动按序求值）
  Step 4: 写入 Excel（全部固化为静态数值），格式化并保存

关键概念：
  - 非计算行：按各自科目代码独立取数填列，不参与任何子项汇总
  - 计算行：备注列为"计算行"（F 列带公式），值按公式计算填充
  - 科目代码格式："1001/2001" = A1411:1001 + A2411:2001

数据单位：
  - A1411/A2411：元
  - 存款归属表输出：万元（自动转换）
  - 附件：元（读取后除以 10000 转换为万元）


3.3 account_checker.py — 科目余额核对表生成引擎
────────────────────────────────────────────────

文件位置：根目录/account_checker.py
类：AccountChecker

功能：
  从科目余额表提取各科目余额，按模板填入科目余额核对表。
  同时从附件2（住房公积金）、附件3（社保基金）、附件4（高管存款）提取数据。

核心方法：
  - load_account_balance(filepath) — 加载科目余额表（支持多 sheet）
  - compute(template, output, att2, att3, att4) — 生成核对表

数据处理流程（4步）：
  Step 1: 按模板中 A 列(科目代码)和 D 列(利息代码)匹配源数据，写入 C/F 列
  Step 2: 从附件读取公积金/社保/高管的本金和利息，填入对应行
  Step 3: 计算各合计行（个人、单位、财政性存款）
  Step 4: 计算境内存款合计和被保险存款余额合计
          （境内存款=个人+单位+财政性+非存款类；其中项住房公积金/
          社保基金存款已含在单位存款中，不重复计入）

安全特性：
  - _safe_set_value / _safe_get_value：自动处理合并单元格（MergedCell）
  - 自动清理科目代码的 .0 后缀（Excel导出常见问题）

关于 c1/c2 调整值：
  - 生成核对表时只填入子项原始合计
  - 调整值在校验步骤中动态应用，不在此处处理
  - 这样校验时可以灵活调整参数，无需重新生成核对表


3.4 validator.py — 数据校验引擎
────────────────────────────────

文件位置：根目录/validator.py
包含4个校验功能：

(1) validate_irp002() — IRP002 校验
    校验内容：
      - 最高偿付限额检查
      - 户均本息合计合理性（≤限额组户均 ≤ 限额；>限额组户均 > 限额）
      - 分组(≤限额 + >限额) vs 总合计 一致性（容差 0.1%）
      - IRP002 vs IRP001 交叉校验（按关键词映射）

(2) validate_deposit_vs_irp001() — 存款归属表 vs IRP001
    校验逻辑：
      - 存款归属表读取"计算行"金额（万元）
      - IRP001 本金扣除久悬户(c3/c4)→/10000→round→精确至万元
      - 两者比较，绝对容差 0.001 元（严格一致，仅消除浮点尾差）

(3) validate_acct_vs_irp001() — 科目余额表 vs IRP001
    校验逻辑：
      - 从核对表明细行按科目代码逐项求和
      - 应用个体工商户调整值(c1/c2)：个人+=，单位-=
      - 与 IRP001 对应项目比较，绝对容差 0.001 元（严格一致）

(4) generate_validation_report() — 全面校验报告
    功能：
      - 从 IRP001、IRP002、存款归属表、科目余额表4个数据源读取数据
      - 逐项比较，输出 Excel 报告
      - 不一致的单元格自动标红（红色底色 #FFC7CE）
      - 一致→输出0，不一致→输出差额

容差规则：三组交叉校验（存款归属表/科目余额核对表/IRP002 vs IRP001）
  均采用绝对容差 0.001 元，即 abs(v1 - v2) <= 0.001
  （严格一致，0.001 仅用于消除浮点精度尾差，超出即判不一致并标红）
  例外：IRP002 内部校验（分组合计 vs 总合计）仍允许 ±max(1, 0.1%) 容差

4.1 存款归属表生成流程
─────────────────────

  A1411 月报表 ──→┐
                   ├──→ DepositCalculator.compute() ──→ 存款归属表_已生成.xlsx
  A2411 月报表 ──→┘                                          （万元）
                        ↑
                   存款归属表模板（templates/）
                   （定义了科目代码映射关系和计算逻辑）

  可选输入：附件2（住房公积金）、附件3（社保基金存款）
  （附件数据仅作为参考记录到日志；计算行按模板公式求和，不直接取附件数）


4.2 科目余额核对表生成流程
─────────────────────────

  科目余额表.xls ──→┐
                     ├──→ AccountChecker.compute() ──→ 科目余额核对表_已生成.xlsx
  核对表模板 ────────→┘

  可选输入：附件2（住房公积金）、附件3（社保基金）、附件4（高管存款）


4.3 校验数据流
─────────────

  ┌─ IRP001（基准数据源）
  ├─ IRP002
  ├─ 存款归属表_已生成
  ├─ 科目余额核对表_已生成
  └─ 调整值（c1/c2/c3/c4）
       │
       ▼
  ValidationSeqThread（顺序执行三项校验）
       │
       ├─ validate_irp002()             → 内部校验 + IRP001交叉校验
       ├─ validate_deposit_vs_irp001()  → 存款归属表 vs IRP001
       └─ validate_acct_vs_irp001()     → 科目余额表 vs IRP001


4.4 校验报告数据流
─────────────────

  IRP001, IRP002, 存款归属表_已生成, 科目余额核对表_已生成
       │
       ▼
  generate_validation_report()
       │
       ▼
  校验报告.xlsx（交叉校验结果，不一致项标红）

五、调整值参数说明（c1/c2/c3/c4）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

参数  含义                单位   应用方式
───────────────────────────────────────────────────────────
c1    个体工商户本金调整值  元    科目余额校验：个人+c1，单位-c1
c2    个体工商户利息调整值  元    科目余额校验：个人+c2，单位-c2
c3    个人久悬户余额        元    存款归属表校验：IRP001个人-c3→/10000

  - c1/c2 仅在科目余额表校验中应用（针对个体工商户会计准则差异）
  - c3/c4 仅在存款归属表校验中应用（久悬户不计入被保险存款）

六、Excel 文件格式说明
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本工具涉及的主要 Excel 文件及其格式要求：

6.1 输入文件
────────────

A1411 月报表 (.xls/.xlsx)
  - 数据从第4行开始（0-indexed row 3）
  - A列 = 科目代码, C列 = 期末余额

A2411 月报表 (.xls/.xlsx)
  - 格式同 A1411

科目余额表 (.xls/.xlsx)
  - 支持多 sheet
  - 数据从第4行开始
  - A列=科目代码, G列=借方余额, H列=贷方余额

IRP001 被保险存款申报表 (.xls/.xlsx)
  - B 列为行标签（"一、境内存款"、"（一）个人存款"等）
  - C 列=本金, D列=应付利息, E列=本息合计

IRP002 存款账户统计表 (.xls/.xlsx)
  - B 列为行标签
  - 列包含：户数合计、≤限额组各列、>限额组各列

附件2/3（住房公积金/社保基金明细表）
  - A列第0行=合计标识, 第6列=本金, 第7列=利息

附件4（高管人员存款统计表）
  - 最后一行=合计, 第7列=本金, 第8列=利息

附件5（保费基数核对表）
  - 第6行开始的数据区域，第1列取调整值

6.2 输出文件
────────────

存款归属表_已生成.xlsx
  - 模板格式：A列=序号, C列=科目代码, D列=名称, E列=符号, F列=金额, G列=备注
  - "计算行"：G列='计算行'的行（F列带公式），金额按公式计算填充
  - 金额单位：万元

科目余额核对表_已生成.xlsx
  - A列=科目代码, B列=科目名称, C列=本金, D列=利息代码, F列=利息
  - 包含合并单元格（安全写入处理）

校验报告.xlsx
  - A列=项目名称, B列=存款归属表差额, C-E列=科目核对表差额, F-H列=IRP002差额
  - 0=一致, 非零值=差额（元）, 红色底色=不一致

八、开发环境搭建
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

8.1 Python 环境
───────────────

  Python 3.8（64-bit 或 32-bit）
  推荐使用 Anaconda 创建独立环境：

    conda create -n py38 python=3.8
    conda activate py38

8.2 安装依赖
───────────

  pip install openpyxl xlrd PyQt5

  依赖清单（最小集合）：
    openpyxl    — 读写 .xlsx 文件
    xlrd        — 读取 .xls 文件（旧版 Excel）
    PyQt5       — GUI 图形界面

  注意：本工具不需要 numpy、pandas、matplotlib 等科学计算库，
        openpyxl 的读写功能是纯 Python 实现，无需这些依赖。

8.3 运行调试
───────────

  直接运行 gui.py 即可启动：

    python gui.py

  或使用 PyInstaller 打包为独立 exe：

    build.bat 64    # 构建 64-bit 版本
    build.bat 32    # 构建 32-bit 版本

8.4 打包注意事项
───────────────

  - 打包前确保 templates/ 目录下有对应银行的模板文件
  - 更新 build.spec 的 datas 列表添加新模板
  - PyQt5 打包后体积较大（~80MB），已通过排除无用模块优化
  - 32-bit 构建需要独立 conda 环境（py38_32）

九、常见问题
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: 提示"未找到匹配文件"怎么办？
A: 工具通过文件名关键词自动匹配。确认工作目录下的文件包含以下关键词：
   - A1411/A2411 → 文件名含 "A1411"/"A2411"
   - 科目余额表 → 文件名含 "科目余额表"
   - IRP001 → 文件名含 "IRP001" 或 "被保险存款申报表"
   - 如果自动匹配失败，可以点击 "..." 按钮手动选择文件。

Q: 不同银行的模板怎么区分？
A: 在 bank_config.py 的 BANK_TYPES 中添加新条目。模板文件放入 templates/ 目录。
   当前只配置了"农村商业银行"一种类型，如需增加按示例格式添加即可。

Q: 校验报告显示红色（不一致）怎么办？
A: 首先确认四个调整值（c1/c2/c3/c4）是否正确。调整值从附件5获取。
   如果调整值正确仍有差异，说明申报数据本身有问题，需回到业务系统核查。

Q: .xls 文件读取报错？
A: 部分新版本的 Excel 保存的 .xls 文件实际是 OOXML 格式。
   工具已自动处理这种情况，会复制为临时 .xlsx 再读取。
   如果仍有问题，建议在 Excel 中另存为 .xlsx 格式。

Q: 生成的归属表数据与 IRP001 对不上？
A: 检查以下可能原因：
   - 久悬户调整值（c3/c4）是否正确
   - 模板中的科目代码映射是否完整
   - A1411/A2411 数据是否是最新的

Q: 打包后 exe 运行时提示缺少模板？
A: 在 build.spec 的 datas 中确认模板文件路径正确：
   datas=[('templates/deposit_template.xlsx', 'templates'), ...]
   打包后重新构建。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

10.1 新增银行类型
─────────────────

  步骤1：在 bank_config.py 的 BANK_TYPES 中添加条目
  步骤2：制作对应的模板文件，放入 templates/ 目录
  步骤3：在 build.spec 的 datas 中注册新模板文件
  步骤4：运行 build.bat 重新打包

10.2 修改校验逻辑
─────────────────

  校验逻辑集中在 validator.py 中：
    - validate_irp002() → IRP002 相关校验
    - validate_deposit_vs_irp001() → 存款归属表校验
    - validate_acct_vs_irp001() → 科目余额表校验
    - generate_validation_report() → 全面校验报告生成

  新增校验项时：
    - 在 _VALIDATION_ITEMS 表中添加行定义
    - 在 _read_irp001_map()/_read_irp002_map() 中添加数据读取
    - 在 _read_deposit_map()/_read_acct_check_map() 中添加映射

10.3 自定义输出格式
───────────────────

  输出格式主要在以下位置控制：
    - deposit_calculator.py → write to Excel 部分（字体、边框、数字格式）
    - account_checker.py → _safe_set_value 调用参数
    - validator.py → _write_cell 函数（样式定义在 _init_styles 中）
