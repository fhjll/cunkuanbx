一、项目概述
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本项目是一个面向银行监管申报的桌面工具，用于：

  1. 生成保费基数核对表  — 一张表内合并三块数据：
       · 存款归属核对（取自 A1411/A2411 月报表，万元）
       · 会计科目核对（取自科目余额表，元）
       · 被保险存款申报表（取自 IRP001 申报表，元）
  2. 执行数据校验        — IRP002 校验 + 保费基数核对表 vs IRP001 校验
  3. 生成校验报告        — 输出标红（不一致）的 Excel 校验报告

业务背景：
  银行每月需向存款保险机构报送被保险存款申报数据（IRP001/IRP002 及附件1~5）。
  其中附件5《保费基数核对表》把"存款归属核对""会计科目核对""被保险存款
  申报表（IRP001）"三块数据放在同一张表内相互核对。
  本工具自动从各报表中提取子项数据，按模板公式计算合并，并交叉校验，
  确保不同数据源之间的数据一致。

  【v11 变更】原"存款归属表"与"科目余额核对表"两张模板已合并为
  一张《保费基数核对表（模板）》，因此：
    - 生成动作合并为一步：生成保费基数核对表
    - 校验动作合并为一项：保费基数核对表 vs IRP001
      （存款归属核对 + 会计科目核对）
    - 调整值（c1~c4）在生成时即写入表中（个体工商户调整项行、Q列），
      校验不再重复调整

技术架构：
  - 编程语言：Python 3.8+
  - GUI框架：PyQt5
  - Excel处理：openpyxl (.xlsx) + xlrd (.xls)，无 numpy/pandas 依赖
  - 打包工具：PyInstaller（发布为独立 exe）

3.1 gui.py — 主程序 / 图形界面（入口文件）
───────────────────────────────────────────

文件位置：根目录/gui.py
功能：启动后显示 PyQt5 单页面窗口，用户通过按钮操作。
依赖：base_checker, validator, bank_config, common

界面布局（从上到下）：
  ① 机构类型选择 — 下拉框选择银行类型（目前仅农村商业银行）
                    +「修改模板…」按钮（打开模板修改窗口）
  ② 工作目录 — 文件夹路径，自动扫描匹配文件
  ③ 调整值设置 — 调整项表格（可自由增删项目，每项配置
                 用途 / 对象 / 字段 / 方式 / 金额）
  ④ 操作按钮 — 3个主要操作 + 进度条
  ⑤ 运行日志 — 黑色背景的日志输出区

3个主要操作（建议按顺序执行）：
  (1) 生成保费基数核对表 → 需要 A1411 + A2411 + 科目余额表 + IRP001
                            （可选 附件2/3/4）
  (2) 执行数据校验       → 需要 IRP001 + 保费基数核对表_已生成
                            （可选 IRP002）
  (3) 生成校验报告       → 需要 IRP001 + IRP002 +（可选）保费基数核对表

调整项设置（可个性化）：
  - 表格列：名称 / 用途 / 对象 / 字段 / 方式 / 金额（元）
      · 用途：会计科目核对（调整会计科目合计，写入表内调整项行）
              存款归属核对（比较时按方式增减 IRP001 本金，写入 Q9/Q10）
      · 对象：个人存款 / 单位存款 / 个人↔单位（一增一减）/
              财政性存款 / 非存款类金融机构存款 / 高级管理人员 /
              不予保险的其他存款
              （用途为存款归属核对时只提供个人/单位，因为校验页只比这两项）
      · 字段：本金 / 应付利息（用途为存款归属核对时固定为本金）
      · 方式：增加 / 扣减
  - 「个人↔单位」表示一增一减：个人按方式增减、单位同步反向。
    个体工商户属于"由单位调整至个人"，用一条记录即可，不必写两条
  - 默认四条标准项（见第五节）：「个体工商户本金」「个体工商户利息」
    为固定标准项，不可删除（灰色底），如不适用把金额改成 0 即可；
    其余项目可自由增删
  - 「从附件5读取」按钮：按银行报送的附件5（Q7~Q10）重建标准调整项，
    金额自动填入；「恢复标准项」按钮恢复默认四条（金额清零）
  - 配置自动保存在工作目录的"调整值配置.json"（切换目录时自动载入；
    再次打开工具时无需重填；旧版拆成两条的配置会自动合并为标准项）

模板修改窗口（「修改模板…」按钮）：
  - 显示模板的候选位置与当前生效来源，优先级：
      ① <工作目录>/模板/<模板文件名>      ← 用户改过的模板（随机构目录）
      ② <程序目录>/templates/<模板文件名> ← 开发模式或 exe 同级目录
      ③ 程序内置模板（打包进 exe，运行时在临时目录，改这里不保留）
  - 按钮：
      · 打开当前模板       —— 用系统默认程序（Excel/WPS）打开生效中的模板
      · 复制到工作目录并打开 —— 复制到 <工作目录>/模板/ 后打开编辑（推荐做法）
      · 用内置模板重置      —— 用内置模板覆盖工作目录模板（恢复到初始版本）
      · 打开所在文件夹 / 刷新
  - 双击列表中的某一行也可直接打开该位置的模板
  - 修改并保存模板后，重新执行「生成保费基数核对表」即使用新模板；
    模板中的行结构、科目代码（C/G/J 列）与公式决定取数与计算口径

文件匹配规则：
  根据 FILE_DEFS 表中的 patterns 关键词自动匹配工作目录下的文件。
  办公软件（WPS/Excel）的临时/锁文件（.~xxx、~$xxx 等）会被自动忽略。
  匹配不到时可以手动选择（点击 "..." 按钮）。

后台线程：
  3个 QThread 子类（BaseCheckThread、ReportGenThread、
  ValidationSeqThread）在后台执行耗时操作，通过 pyqtSignal 通信。


3.2 base_checker.py — 保费基数核对表生成引擎【核心】
────────────────────────────────────────────────────

文件位置：根目录/base_checker.py
类：BaseChecker

功能：
  按《保费基数核对表（模板）》把三块数据填进同一张表，再按模板公式
  对子项数据逐级计算合并，并把结果固化为静态数值。

表结构（模板固定列）：
  顺序 | 行列名称 | 存款归属核对（子项代码/子项名称/符号/本金，万元）
        | 会计科目核对（本金代码/科目名称/金额；利息代码/科目名称/金额；合计，元）
        | 被保险存款申报表 IRP001（本金/利息/合计，元）| 差额说明

核心方法：
  - load_a1411(filepath)          — 加载 A1411（万元）
  - load_a2411(filepath)          — 加载 A2411（万元）
  - load_account_balance(path)    — 加载科目余额表（元，多 sheet）
  - load_irp001(path)             — 加载 IRP001 本金/应付利息（元）
  - load_attachments(att2,att3,att4)
  - set_adjustments(c1, c2, c3, c4)
  - compute(template, output)     — 执行计算并输出 .xlsx

计算流程（先按模板公式算，再叠加调整项）：
  ...详见 3.2 内的步骤说明
  Step 1 读模板：解析每行的子项代码（C列）、科目代码（G列本金 / J列利息）
         以及 F/I/L/M/N/O/P 各列公式（含共享公式，转换模板时已展开为逐格公式）
  Step 2 明细取数：
         · 存款归属核对（F列）：按子项代码从 A1411/A2411 取数（万元）
         · 会计科目核对（I/L列）：按科目代码从科目余额表取数（元）
         · IRP001（N/O列）：按行标签从 IRP001 申报表取数（元）
         · 个体工商户调整项：本金/利息各写入"（＋）/（－）"两行
           （个人加、单位减，由模板公式自动实现）
         · 高级管理人员存款：按附件4填入明细行
  Step 3 计算最终结果（三小步，关键）：
         3a 按模板公式逐条求值 → 基础结果（支持单元格引用、SUM区域、
            ROUND、IF、比较与四则运算；跨表引用自动去前缀），
            得到个人/单位/财政性/非存款类/高管/不予保险/被保险存款合计
            ※ 程序内不内置任何计算公式：F 列存款归属、I/L/M 会计科目、
              N/O/P 申报表列、校验页差额全部读自模板；模板没写的公式
              就不计算。公式若引用了没有子项代码的行，日志会提示
              （如"F11 引用了 F60，但该行没有子项代码，取数为 0"），
              提示去改模板，而不是由程序自行补数
         3b 按调整项对相应合计项做调整：最终值 = 模板公式结果 ± 调整额
            （日志打印"模板公式结果 X + 调整 Y = 最终 Z"），
            并重算受影响的派生公式（合计列 M、被保险存款合计等）
            —— 调整额叠加在合计上，不依赖模板里是否有"调整项行"
         3c 若模板中能定位到"调整项"行（无科目代码的人/单位调整行），
            把调整额同时写入该行作为展示值（与银行附件5 对照用）；
            定位不到时仅日志提示，不影响最终结果
  Step 4 固化输出：把最终结果、调整值（Q列）与校验页差额写入 .xlsx
         （覆盖公式，全部为静态数值；被调整过的合计单元格带批注说明
          "模板公式结果 ± 调整项 = 最终值"）

关于模板公式（重要）：
  - 财性存款的"1. 国库定期存款/2. 代理财政性存款"两行在合并模板中没有
    子项代码（代码列在下方的明细行），其 F 列金额按 VIRTUAL_F_ROWS 常量
    对应的代码取数（12MIS/22MIS、12MIM/22MIM）
  - 合并模板未给出"二、境外存款"三个合计行的公式，工具按原《存款归属表》
    模板口径补算（EXTRA_FORMULAS：境外个人/单位/同业存放合计）
  - 调整值写入 Q 列（差额说明列）前四格 Q7~Q10，同时作为校验页公式输入

参考值记录（仅记录到日志）：
  - 附件2（住房公积金）本金合计、附件3（社保基金）本金合计

3.3 tools/convert_xls_template.py — 表样转换工具（开发用）
──────────────────────────────────────────────────────────

功能：把监管下发的 .xls（BIFF8）表样转换为等价的 .xlsx 模板，供程序
      内嵌使用。转换内容：单元格值、公式（共享公式 SHRFMLA 展开为逐格
      显式公式）、合并单元格、列宽行高、字体/边框/填充/数字格式、批注。

用法：
  python tools/convert_xls_template.py 保费基数核对表（模板）.xls \
         templates/保费基数核对表（模板）.xlsx

说明：
  - 监管表样更新后，重新执行一次转换并替换 templates/ 下的 .xlsx 即可；
  - 批注（说明调整值口径）按内容关键词映射到固定单元格（_NOTES_BY_KEYWORD）；
  - 只支持 BIFF8 的 .xls；若文件实为 OOXML，直接改扩展名为 .xlsx 即可。


3.4 validator.py — 数据校验引擎
────────────────────────────────

文件位置：根目录/validator.py
包含3个校验功能：

(1) validate_irp002() — IRP002 校验
    校验内容：
      - 最高偿付限额检查
      - 户均本息合计合理性（≤限额组户均 ≤ 限额；>限额组户均 > 限额）
      - 分组(≤限额 + >限额) vs 总合计 一致性（容差 0.1%）
      - IRP002 vs IRP001 交叉校验（按关键词映射）

(2) validate_base_check_vs_irp001() — 保费基数核对表 vs IRP001
    校验逻辑（与模板校验页口径一致）：
      (a) 存款归属核对（F列，万元）：
            个人存款：F7 = ROUND((IRP001个人本金 - c3) / 10000)
            单位存款：F8 = ROUND((IRP001单位本金 - c4) / 10000)
            财政性 / 非存款类：F11 = ROUND(IRP001本金 / 10000) 等
          c3/c4 优先取界面填写值，为 0 时取表内 Q9/Q10
      (b) 会计科目核对（I/L/M列，元）：
            个人/单位/财政性/非存款类/高管/不予保险/被保险存款合计
            与 IRP001 本金、应付利息、合计比较，绝对容差 0.001 元
            （个体工商户调整项已计入表内，不再重复调整）
      (c) 提供 IRP001 文件时，核对表内 N/O 列取数是否与申报表一致
      (d) 提供 c1/c2 时，核对表内"个体工商户调整项"行与界面值是否一致

(3) generate_validation_report() — 全面校验报告（Excel）
    以 IRP001 为基准，逐项输出三组差额，不一致标红：
      B列    存款归属核对 vs IRP001（万元，按 c3/c4 调整后比较）
      C/D/E列 会计科目核对 vs IRP001（本金/利息/合计，元）
      F/G/H列 IRP002 vs IRP001（本金/利息/合计，元）

容差规则：
  - 存款归属核对：比较"四舍五入至万元"后的数值（差额=0 即一致）
  - 会计科目核对、IRP002 交叉校验：绝对容差 0.001 元
    （严格一致，0.001 仅用于消除浮点精度尾差，超出即判不一致并标红）
  - 例外：IRP002 内部校验（分组合计 vs 总合计）仍允许 ±max(1, 0.1%) 容差

五、调整值（调整项）说明
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

调整值是"源数据与申报表之间的口径差异"，可自由增删项目。
每个调整项由五个要素构成：

  要素    取值                     说明
  ─────────────────────────────────────────────────────────────
  名称    自定义文字               便于识别，不影响计算
  用途    会计科目核对             调整会计科目合计（写入表内"调整项"行）
          存款归属核对             比较时按方式增减 IRP001 本金（写入 Q9/Q10）
  对象    个人存款 / 单位存款      会计科目核对：作用于对应合计项
          个人↔单位               一增一减（个人按方式增减、单位同步反向）
          财政性存款 / 非存款类    其他合计项：调整额直接并入该合计项的
          金融机构存款 / 高级      公式（模板没有专门调整行）
          管理人员 / 不予保险的
          其他存款
  字段    本金 / 应付利息          调整作用于本金还是利息
          （用途=存款归属核对时固定为本金，因为该比较只比本金）
  方式    增加 / 扣减              加进去还是扣出来
  金额    数值（元）

标准口径（工具默认给出、也可从附件5 一键重建，共四条；
前两条为固定标准项，不可删除）：

  名称            用途          对象       字段      方式   生效位置
  ────────────────────────────────────────────────────────────────
  个体工商户本金  会计科目核对  个人↔单位  本金      增加   个人行 I +c1、单位行 I +c1
  个体工商户利息  会计科目核对  个人↔单位  应付利息  增加   个人行 L +c2、单位行 L +c2
                                                          （单位行被模板公式扣减，
                                                            故填正数＝从单位扣减的金额）
  个人久悬户      存款归属核对  个人存款   本金      扣减   Q9
  单位久悬户      存款归属核对  单位存款   本金      扣减   Q10

计算方式（在生成/校验中如何生效）：
  - 用途=会计科目核对：同类同字段的调整项按方式求和后写入表内
      · 个人存款行（模板"（＋）"行）：本金→I 列，利息→L 列
      · 单位存款行（模板"（－）"行）：本金→I 列，利息→L 列
      · 对象=个人↔单位 的项目同时计入两侧：个人侧按方式增减、
        单位侧反向（个体工商户本金/利息即此口径，一条记录等于原来的
        "个人增 + 单位减"两条）
    再由模板公式并入个人/单位存款合计：
      · 个人行（＋）在 SUM 内 → 填"应加进个人存款的金额"
      · 单位行（－）被公式扣减（I8=SUM(I25:I37)-I38-I39）
        → 填"应从单位存款扣减的金额"，即个体工商户在个人行、单位行都填正数
        （与银行附件5 的填写口径一致）
  - 对象=其他合计项（财政性存款/非存款类金融机构存款/高级管理人员/
    不予保险的其他存款）：模板没有专门的调整行，调整额直接并入该合计项的
    公式后再参与计算，因此该合计项以及上层汇总（被保险存款合计等）
    都会同步反映；调整内容记录在该合计单元格的批注里
  - 调整项行定位：优先按模板中的"调整项"名称（＋=个人侧、－=单位侧）；
    若模板中名称被改掉/删掉，则按公式结构兜底定位
    （个人侧=个人合计 SUM 区域最后一行，单位侧=单位合计公式中被减去的、
    无科目代码的行），并在输出表中把缺失的行名称补回
    「个体工商户调整项（本金/应付利息）（＋/－）」
  - 用途=存款归属核对：按对象汇总为"应从 IRP001 本金中扣减的净额"
      · 方式=扣减 记正数（减少 IRP001 侧）、方式=增加 记负数（加回）
      · 个人 → Q9、单位 → Q10；对象=个人↔单位 时个人侧减少、单位侧增加
      · 校验时按  ROUND((IRP001本金 - 该净额) / 10000)  与存款归属（万元）比较
  - 表内 Q7/Q8 保存"由单位调整至个人"的个人侧净额（本金/利息），
    与银行报送附件5 的口径一致，便于外部核对与下期沿用

业务口径（模板批注）：
  - 个体工商户：由单位调整至个人部分的本金/应付利息
  - 个人久悬户 = 历史值（个人部分）+ 久悬不动户余额（22410401）
  - 单位久悬户 = 历史值（单位部分）+ 久悬不动户余额（22410402）
                 + 久悬未取款收入（630108）- 久悬未取款支出（671106）

历史值行（模板第23/37行"历史久悬未取款转收入（个人/单位部分）"）：
  - 这两行在模板中没有科目代码，无法从科目余额表取数，属于"每年度末重新
    调整、一个会计年度内固定"的历史值，由银行在其附件5 中填写
  - 工具不填这两行（留空），因此会计科目"单位存款"（或"个人存款"）与
    IRP001 的差额通常恰好等于对应历史值：
      咸宁202609：单位差 9,298,118.57 = 附件5 第37行历史值
      崇阳202609：单位差 5,942,674.36 = c4 口径中的"历史值（单位部分）"
      通城202609：个人差 2,609,344.37 = 附件5 第23行历史值
  - 如需把历史值并入表内，可在模板第23/37行手工填写后重新生成，
    或作为额外调整项处理

  - 位置：工作目录（每个机构一份），内容为 {"items": [ ... ]}
  - 切换工作目录时自动载入；生成/校验/报告前自动保存

8.1 Python 环境
───────────────
  Python 3.8+（64-bit 或 32-bit），推荐 Anaconda 独立环境：
    conda create -n py38 python=3.8
    conda activate py38

8.2 安装依赖
───────────
  pip install openpyxl xlrd PyQt5

  依赖清单（最小集合）：
    openpyxl    — 读写 .xlsx 文件
    xlrd        — 读取 .xls 文件（旧版 Excel，2.x 版本仅支持 .xls）
    PyQt5       — GUI 图形界面

8.3 运行调试
───────────
  python gui.py                # 启动图形界面
  或
  build_win7.ps1               # 打包 Windows 可执行文件

8.4 表样更新
───────────
  监管下发新的 .xls 表样时：
    1. python tools/convert_xls_template.py <新表样>.xls templates/保费基数核对表（模板）.xlsx
    2. 核对转换结果（公式数、合并区域数、批注数）
    3. 如科目代码/行结构有变化，检查 base_checker.py 中的常量：
       VIRTUAL_F_ROWS（无代码的财政性拆分行）、EXTRA_FORMULAS（境外合计）、
       ADJ_CELLS（调整值写入位置）

九、常见问题
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: 提示"未找到匹配文件"怎么办？
A: 工具通过文件名关键词自动匹配。确认工作目录下的文件包含以下关键词：
   - A1411/A2411 → 文件名含 "A1411"/"A2411"
   - 科目余额表 → 文件名含 "科目余额表" 或 "科目余额查询报表"
   - IRP001 → 文件名含 "IRP001" 或 "被保险存款申报表"
   - 附件5 → 文件名含 "附件5" 或 "保费基数核对表"
   如果自动匹配失败，可以点击 "..." 按钮手动选择文件。

Q: 调整项怎么填？能从附件5 自动读取吗？
A: 可以。工作目录中存在银行报送的附件5《保费基数核对表》时，工具自动读取
   其 Q7~Q10 并按标准口径重建六条调整项（个体工商户本金/利息、
   个人/单位久悬户）。也可点「从附件5读取」按钮随时重建，
   或手工增删项目、修改金额；配置会保存在工作目录的"调整值配置.json"，
   下次自动载入。口径见模板内批注与本文档第五节。

Q: 一笔调整要同时影响个人和单位（如个体工商户存款）怎么填？
A: 对象选「个人↔单位」（一增一减），一条记录即可：个人按方式增减、
   单位同步反向。个体工商户本金/利息就是这两条标准项，改金额即可。
   若确实只需影响单侧，对象选「个人存款」或「单位存款」。

Q: 能给"财政性存款"等合计项也加调整项吗？
A: 可以。调整项的"对象"下拉里除个人/单位外，还提供财政性存款、
   非存款类金融机构存款、高级管理人员、不予保险的其他存款；这类调整额
   会直接并入该合计项的公式，合计项与上层汇总一并生效，并在单元格批注
   中记录调整明细。注意"存款归属核对"只支持个人/单位调整项
   （校验页只对这两项做久悬户调整）。

Q: 模板里"个体工商户调整项"那两行的名称被我删了/改了会怎样？
A: 不影响使用。工具优先按名称定位调整项行，名称缺失时改按公式结构定位
   （个人侧=个人存款合计 SUM 区域最后一行；单位侧=单位合计中被减去的
   无科目代码行），并在生成的表中把行名称补回"个体工商户调整项
   （本金/应付利息）（＋/－）"，同时在运行日志中提示。若两行都定位不到，
   日志会给出"未定位到调整项行"的警告。

Q: 「个体工商户本金/利息」为什么删不掉？
A: 这两条是固定标准项（灰色底），避免误删导致核心口径调整丢失。
   本行不适用时把金额改成 0 即可；确实需要额外项目时用「＋添加项目」。

Q: 校验报告显示红色（不一致）怎么办？
A: 先确认调整值（c1~c4）是否正确；调整值正确仍有差异时，说明申报数据
   本身存在差异，需回到业务系统核查。常见差异点：
   - 单位存款：科目余额表（含"个体工商户调整项""营业外收入/支出-久悬未取款项"）
     与 IRP001 单位存款本金不一致，需逐科目比对
   - 存款归属核对差额≠0：A1411/A2411 存款归属与 IRP001 扣久悬户后
     不能四舍五入到同一万元数

Q: 校验页的"存款归属差额"为什么是 0 却看不到明细？
A: 存款归属核对采用"四舍五入至万元后比较"的口径，不足万元的尾差会被舍去；
   需要看元级差异时请对照 IRP001 与 A1411 原始数据。

Q: 启动时报 "Could not find the Qt platform plugin"（cocoa/windows）怎么办？
A: 说明 PyQt5 找不到 Qt 平台插件。常见于用 conda 安装的 PyQt5：
   conda 的 qt-main 把插件放在环境根目录（<环境>/plugins、
   Windows 为 <环境>\Library\plugins），而 Qt 只在 PyQt5 包内查找。
   程序启动时已自动探测并补充该路径（gui.py 的 _setup_qt_plugin_paths()），
   正常情况无需手工处理；如果仍报错，可临时指定环境变量后运行：
     macOS/Linux:  export QT_QPA_PLATFORM_PLUGIN_PATH=<环境>/plugins/platforms
     Windows CMD:  set QT_QPA_PLATFORM_PLUGIN_PATH=<环境>\Library\plugins\platforms
   或改用 pip 安装的 PyQt5：pip install PyQt5

Q: 想改模板（比如调整科目代码、行说明、公式）怎么做？
A: 点界面顶部「修改模板…」→「复制到工作目录并打开」，模板会被复制到
   <工作目录>/模板/ 并在 Excel/WPS 中打开；改完保存后重新生成即生效。
   该副本只对当前工作目录生效，不影响其他机构；想恢复初始版本点
   「用内置模板重置」即可。打包运行时程序内置模板在临时目录，直接改
   那里不会保留，必须按上述方式复制出来改。

Q: 启动时提示 "missing font family Microsoft YaHei" 有什么影响？
A: 无影响。macOS/Linux 上没有"微软雅黑"字体，Qt 会自动选择替代字体；
   在 Windows 上（打包 exe 的运行环境）字体正常。

Q: .xls 文件读取报错？
A: 部分新版本的 Excel 保存的 .xls 文件实际是 OOXML 格式。
   工具已自动处理这种情况，会复制为临时 .xlsx 再读取。
   如果仍有问题，建议在 Excel 中另存为 .xlsx 格式。

Q: 生成的保费基数核对表与银行报送的附件5数字不同？
A: 工具是按"源数据 + 模板公式"重新计算的，用于核对银行的申报是否
   与源数据相符；两者不同正是需要关注并说明的差异。常见差异点：
   - 第23/37行"历史久悬未取款转收入（个人/单位部分）"：模板无科目代码，
     工具留空（银行附件5 中有历史值）→ 会计科目单位/个人存款可能相差
     该历史值金额
   - 明细行的"合计"列（M列）：工具按"本金+利息"补算，银行附件5 通常
     只填汇总行
   - "差额说明"列（Q列）：工具清空模板遗留的示例文字，请按本期差异填写

Q: 合并模板里没有"境外存款"合计公式，工具怎么处理？
A: 工具按原《存款归属表》模板口径补算境外个人/单位/同业存放三个合计
   （见 base_checker.EXTRA_FORMULAS），仅用于展示与报告比对，
   不参与模板校验页。

10.1 新增银行类型
─────────────────
  步骤1：在 bank_config.py 的 BANK_TYPES 中添加条目
         （base_check_template 指向对应模板）
  步骤2：制作对应的模板文件（可先用 tools/convert_xls_template.py 转换）
         放入 templates/ 目录
  步骤3：运行打包脚本重新打包（templates/ 目录整体打包）

10.2 修改校验逻辑
─────────────────
  校验逻辑集中在 validator.py 中：
    - validate_irp002()               → IRP002 相关校验
    - validate_base_check_vs_irp001()  → 保费基数核对表校验
    - _read_base_check_map()           → 从核对表读取三块数据（改列位置时改这里）
    - generate_validation_report()     → 全面校验报告生成（_VALIDATION_ITEMS 定义行）

  新增校验项时：
    - 在 _VALIDATION_ITEMS 表中添加行定义
    - 在 _read_irp001_map()/_read_irp002_map() 中添加数据读取
    - 在 _read_base_check_map() 中添加映射

10.3 修改生成本逻辑
───────────────────
  生成逻辑集中在 base_checker.py 中：
    - 取数规则：lookup_monthly() / lookup_acct() / load_irp001()
    - 行结构常量：VIRTUAL_F_ROWS / EXTRA_FORMULAS / ADJ_CELLS / IRP001_ITEM_KEYS
    - 公式求值：_eval_formula()（支持 SUM / ROUND / IF / 比较 / 四则运算）
  输出格式（字体、边框、数字格式）继承模板设置，仅补数字格式。

10.4 用模板控制计算口径（推荐）
────────────────────────────────
  所有计算都由模板决定，改模板即可改口径，无需改程序：
    · 合计范围：把 I7 写成 =SUM(I14:I21) 还是 =SUM(I14:I23)-I24，
      决定个人存款汇总到哪几行
    · 需要参与合计的行为何不在 SUM 区域里、是否加项减项，全在公式里表达
    · 会计科目"合计项"的调整（个人/单位/财政性/非存款类/高管/不予保险）
      由界面"调整项"配置，最终值 = 模板公式结果 ± 调整额
    · 校验页的比较口径（B/C/D/E/F 列公式）同样读自模板
  规则：模板公式引用的单元格必须有数据来源——
    · 存款归属列：该行要有子项代码（C 列），否则取数为 0（日志会提示）
    · 会计科目列：该行要有科目代码（G/J 列），或由附件4/历史值等填入
  调整项所在的单元格（如 Q9/Q10）也由校验页公式引用位置决定，程序不写死。

10.5 自定义输出格式
───────────────────
  - 保费基数核对表：由模板文件决定（改格式请改模板）
      · 界面上点「修改模板…」→「复制到工作目录并打开」，
        改完保存即对当前工作目录生效（不动程序目录模板）
      · 若要改全局默认：改 templates/保费基数核对表（模板）.xlsx，
        或从监管 .xls 表样重新转换（见 8.4）
  - 校验报告：validator.py → _init_styles() 与 _write_cell()
